# 安全生产检测方案A实施文档（YOLO 检测 + 规则判定）

本方案用于快速落地安全生产视觉检测，采用“先检测物体，再用规则判定违规”的方式。

方案A固定类别为：

- `person`
- `helmet`
- `vest`

不直接训练 `no_helmet`、`no_vest`，而是在推理阶段通过匹配规则判断违规，便于扩展和迭代。

---

## 1. 目标与适用范围

### 1.1 目标

- 检测人员是否佩戴安全帽
- 检测人员是否穿反光衣
- 支持危险区域内人员违规告警（可选）

### 1.2 适用场景

- 工地出入口
- 厂区作业面
- 仓储装卸区
- 夜间值守监控（需补夜间数据）

---

## 2. 为什么选方案A

- 类别更稳定：`person/helmet/vest` 通用性高
- 数据更易积累：不用频繁定义新的违规类
- 规则更灵活：后续可增加“区域、时长、班组、时间段”等约束
- 迁移更方便：换场景时主要调规则，不必重做全部类别体系

---

## 3. 数据标准（必须统一）

### 3.1 标注类别定义

- `person`：完整人或可判定为人的主体（含部分遮挡）
- `helmet`：可见且能判定为安全帽的目标
- `vest`：可见且能判定为反光衣/安全背心的目标

### 3.2 标注原则

- 框贴边：框尽量贴合目标外轮廓
- 一致性：同类目标标注尺度一致
- 不可判定不标：严重模糊或遮挡导致不可判定时不标
- 小目标规则统一：例如小于 8px 的帽子不标（团队先约定）

### 3.3 数据覆盖要求

- 光照：白天、夜间、逆光、阴影
- 视角：俯视、平视、斜视
- 距离：近景、中景、远景
- 密度：单人、多人密集
- 干扰：反光物体、类似颜色背景、遮挡物

### 3.4 数据量建议（一期可用）

- `person`：3000+ 框
- `helmet`：3000+ 框
- `vest`：3000+ 框

图片划分建议：

- 训练集：70%
- 验证集：20%
- 测试集：10%

---

## 4. 训练配置（YOLO）

### 4.1 推荐起步参数

- 模型：`yolo11n.pt`（先跑通）
- 图像尺寸：`imgsz=640`
- 轮数：`epochs=120`
- 批次：`batch=16`（显存不足用 `8`）
- 设备：优先 GPU

### 4.2 第二阶段提精度

- 模型升级：`yolo11s.pt` 或 `yolo26n.pt`
- 轮数：`epochs=150~200`
- 保持 `imgsz=640`，必要时尝试 `768`

### 4.3 验收指标（模型层）

- `mAP50` >= 0.80（一期可试运行）
- `Recall` 优先于 `Precision`（安全场景更怕漏报）
- 分类别看指标：重点看 `helmet`、`vest` 的召回率

---

## 5. 规则判定逻辑（核心）

模型只负责检测，违规由规则模块判定。

### 5.1 基础判定流程

1. 检测出所有 `person` 框
2. 检测出所有 `helmet` 和 `vest` 框
3. 对每个 `person`，在其区域内做匹配：
   - 匹配到 `helmet` -> 认为“戴帽”
   - 匹配到 `vest` -> 认为“穿衣”
4. 无匹配则判定违规：
   - 无帽 -> `no_helmet_event`
   - 无反光衣 -> `no_vest_event`

### 5.2 匹配建议

- 帽子匹配区域：`person` 上半区域（如上 40%）
- 反光衣匹配区域：`person` 中部区域（如中间 50%）
- 使用 IoU 或中心点落入区域作为匹配条件

### 5.3 时序去抖（必须）

- 连续 N 帧（建议 5~10 帧）违规才触发
- 同一跟踪 ID 在冷却时间内只报警一次（如 60 秒）
- 人员离开画面后重置状态

---

## 6. 区域与场景规则（可选增强）

- 仅在 ROI（危险区域）内判定 PPE 违规
- 非作业时间降低告警等级或不告警
- 按摄像头单独配置阈值（不同机位效果差异大）

---

## 7. 上线验收标准（业务层）

建议在真实视频回放上验收，不只看离线指标。

- 未戴帽事件召回率 >= 90%
- 未穿反光衣事件召回率 >= 90%
- 单路摄像头误报 <= 3 次/小时（可按场景调整）
- 告警延迟 <= 3 秒（按系统资源评估）

---

## 8. 部署建议

- 边缘侧：ONNX Runtime / TensorRT（低延迟）
- 服务侧：统一事件上报接口（含摄像头ID、时间、截图、违规类型）
- 平台侧：事件闭环（确认、误报标记、派单处理）

---

## 9. 迭代闭环（每周执行）

1. 收集误报与漏报片段
2. 人工复核并补标
3. 增量并入训练集
4. 复训并与上版对比
5. 更新规则参数（阈值、帧数、冷却时间）

建议每 2~4 周形成一个稳定版本。

---

## 10. 配置模板（可直接复用）

```yaml
project_name: safety_ppe_a
classes: [person, helmet, vest]
train:
  model: yolo11n.pt
  imgsz: 640
  epochs: 120
  batch: 16
  conf_threshold: 0.25
rules:
  helmet_match_region: top_40_percent
  vest_match_region: middle_50_percent
  trigger_frames: 8
  cooldown_seconds: 60
  roi_enabled: true
```

---

## 11. 一期最小可用版本（MVP）范围

- 检测：`person/helmet/vest`
- 判定：未戴帽、未穿反光衣
- 告警：带去抖与冷却机制
- 统计：按摄像头输出日/周违规趋势
